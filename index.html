MediaSource Extensions append performance

Test overview

Each test repeatedly appends 2.5MiB worth of MP4 AAC audio and/or MP4 h264 video in separate SourceBuffers simultaneously and measures:

  • updateend audio: Time between appendBuffer() and the corresponding 'updateend' event in that SourceBuffer.
  • post-update: Time between the last required updateend and 'canplaythrough'.
  • canplaythrough: Time between the first appendBufer() and the 'canplaythrough' event.

The media files are downloaded only once before the start of the tests and reused for all iterations.

This test is equivalent to VideoBufferSpeed in the YouTube MSE Conformance Tests, but more amenable for measurement and debugging.

Once all iterations are done, the table of measurements is also printed via console.log() in both Markdown and JSON to make it easier to share and store results.

Test options

You can customize the behavior of this test page with URL query parameters:

  • ?video: Include a video SourceBuffer. Omit this parameter to not use a video SourceBuffer. At least one of either ?audio or ?video must be used.
  • ?audio: Include an audio SourceBuffer. Omit this parameter to not use an audio SourceBuffer.
  • ?no_log: Disables console.log() logging.
  • ?rest=NUMBER: Time in milliseconds to wait between test iterations. Defaults to 100ms. A value of 0 makes use of setTimeout(cb, 0). If a negative value is provided iterations are chained together within any calls to setTimeout().
  • ?max_iter=NUMBER: Number of iterations where meausurements will be considered valid. Defaults to 30. You can set a very large number (e.g. 99999999999) for continuous looping (useful when profiling).
  • ?priming=NUMBER: Number of priming iterations. Defaults to 3. These iterations are run before the main iterations but their measurements are discarded.
  • ?tag=TEXT: If present, show TEXT above the table. This is useful for tagging different builds of browsers during testing.
